## Findings

### CRITICAL

**[CRITICAL] `output/web/src/lib/api.ts:39` and `output/api/app/dependencies.py:20-26` - Auth system entirely broken: httpOnly cookie is unreadable by JavaScript but the backend requires an Authorization header**

The backend sets the JWT as an `httpOnly` cookie (`auth.py:53-54`). `httpOnly` cookies are never exposed via `document.cookie` and are therefore permanently invisible to JavaScript. The frontend interceptor at `api.ts:39` calls `getCookie("receipts_token")` which always returns `null` for httpOnly cookies. The Authorization header is therefore never set on any request.

`_get_bearer_token` in `dependencies.py:20-26` reads exclusively from the `Authorization: Bearer` header and raises a 401 if absent. The browser sends the cookie automatically (because of `withCredentials: true`) but the backend ignores it.

Consequence: every call to a protected endpoint returns 401 immediately. The app is non-functional for any logged-in user.

Fix: In `dependencies.py`, modify `_get_bearer_token` to also check `request.cookies.get("receipts_token")` as a fallback when the Authorization header is absent.

### HIGH

**[HIGH] `output/api/app/routers/profiles.py:149-205` - N+1 query in GET /profiles/{slug}/skills**

For each of N skills, a separate DB query fetches top-3 evidence chunks. A user with 80 skills triggers 81+ queries on the hot public-profile read path.

Fix: Use a single CTE with `ROW_NUMBER() OVER (PARTITION BY skill_evidence_id ORDER BY relevance_score DESC)` to retrieve top-3 per skill in one pass.

**[HIGH] `output/api/app/workers/index_tasks.py:212-228` - N+1 SHA existence check per commit**

For every raw commit SHA, a separate `SELECT` query checks if the SHA exists. 500 commits = 500 sequential queries.

Fix: Fetch all existing SHAs in one query, diff in Python with a `set`.

**[HIGH] `output/api/app/routers/index.py:39-64` - Race condition in "check for active job, then create job"**

Two concurrent POST /index requests can both pass the `active_job is None` check before either commits a row.

Fix: Add a `UNIQUE (user_id)` partial index on `index_jobs` filtered to `status IN ('queued', 'running')` enforced at the DB level; catch `IntegrityError` and return 409.

**[HIGH] `output/docker-compose.yml` - `web` service is missing**

The `web` Dockerfile exists at `output/web/Dockerfile` but the compose file has no `web` service.

Fix: Add `web` service exposing port 3000 with `depends_on: api`.

### MEDIUM

**[MEDIUM] `output/api/app/routers/chat.py:158-171` - Rate-limit TOCTOU: GET then INCR are not atomic**

Two concurrent requests both read `count=19`, both pass the check, both proceed.

Fix: INCR first, set TTL on first write, then check if result exceeds limit.

**[MEDIUM] `output/api/app/routers/auth.py:90-92` - GitHub callback has no error handling when user denies OAuth**

GitHub redirects with `error=access_denied` instead of `code` when user cancels. FastAPI returns raw 422.

Fix: Make `code`, `state` optional; add `error: str | None` param; redirect to frontend with error status.

**[MEDIUM] `output/api/app/services/retriever.py:33-53` - Cosine distance computed twice**

`dc.embedding <=> CAST(:embedding AS vector)` is evaluated once in WHERE and once in ORDER BY.

Fix: Wrap in a CTE that aliases the distance once; filter and sort on the alias.

**[MEDIUM] `output/api/app/routers/repositories.py:67-73` - Redis connection leaked on upsert failure**

`finally: await r.aclose()` is not guaranteed on all early-exit code paths.

Fix: Single top-level `try/finally: await r.aclose()` wrapping the entire function body.

**[MEDIUM] `output/web/src/hooks/useAuth.ts` and `output/web/src/lib/api.ts` - No 401 interception clears stale auth state**

After JWT expiry, Zustand still shows the user as authenticated; all API calls silently fail.

Fix: Add response interceptor calling `clearAuth()` on 401.

**[MEDIUM] `output/api/app/workers/index_tasks.py:165-173` - `is_indexed=True` even when all repos fail**

Fix: Count successful repos; only set `is_indexed=True` if at least one succeeded.

**[MEDIUM] `output/web/src/components/profile/IndexingPollerClient.tsx:22` - Misleading comment; `useProfile` has no `refetchInterval`**

Fix: Add `refetchInterval` to `useProfile` or remove the misleading comment.

**[MEDIUM] `output/api/app/services/embeddings.py:51-58` - Silent zero-vector substitution drops indexed data**

On OpenAI API failure, `[0.0] * 1536` vectors are substituted silently. Zero vectors never satisfy the 0.70 cosine threshold, making chunks permanently unretrievable.

Fix: Track zero-vector count and surface it in job status.

## Architecture Assessment

Layering is clean: thin routers, service objects, ORM models, Pydantic schemas, Celery asyncio bridge. The pgvector approach (avoiding a separate vector service) is appropriate for MVP scale.

**Scalability risks:**
- N+1 in `GET /profiles/{slug}/skills` is the most urgent problem - this is on the hot public-profile read path
- Per-commit SHA check loop: 20 repos x 500 commits = 10,000 queries per indexing job
- Redis connection pools created per-request rather than a module-level singleton

**Bad decisions:**
- httpOnly-cookie-plus-Authorization-header split: architecture correctly chose httpOnly cookie but implementation broke authentication by requiring the Authorization header instead
- `python-jose` has a history of security issues; `PyJWT` is preferred for new projects (mitigated by explicit `algorithms=["HS256"]`)
