# DriftGuard

## One-liner
A CLI and MCP server that catches schema drift between your OpenAPI spec, TypeScript types, and database schema - surfacing mismatches directly inside AI coding agents before they ship broken code.

## The wow hook
Every time Cursor or Claude Code edits one layer of your API stack - the TypeScript type, the OpenAPI spec, or the Prisma schema - the other two quietly fall out of sync. Nobody notices until something breaks in production. DriftGuard is a single `npx driftguard check` that tells you exactly which fields disagree across all three layers, and because it runs as an MCP server, your AI coding agent knows about the drift before it writes the next line of code.

## Who it's for
- TypeScript backend developers using AI coding tools (Cursor, Claude Code, Copilot) who ship features daily and don't manually keep three files in sync
- Open source library maintainers who publish OpenAPI specs alongside their SDK and need a CI check to ensure the spec matches the actual implementation
- Platform teams enforcing API governance across microservices without buying an enterprise API management platform

## Why now / why it doesn't exist yet
Three reasons this is a 2026 idea:

1. **Optic just died.** The leading open source API drift detection tool (Optic, YC-backed) was acquired by Atlassian in April 2024 and its GitHub repo was archived on January 12, 2026. There is no strong open source replacement. oasdiff handles spec-to-spec diff only. PactFlow and Speakeasy are commercial. A gap opened this year.

2. **AI coding tools created a new category of drift.** Cursor reached $2B ARR in early 2026. Claude Code, Copilot, and others are now the primary way teams write code. These tools write code fast but they only update the file they are looking at - they update a TypeScript type without touching the OpenAPI spec, or add a Prisma field without regenerating the response schema. Schema drift used to happen slowly; it now happens on every PR.

3. **MCP makes a new integration layer possible.** The Model Context Protocol (Anthropic, late 2024) became the standard for AI tool integration in 2025. No drift detection tool has been built as an MCP server. That means AI coding agents today have zero awareness of schema inconsistencies in the codebase - they just keep writing against whatever context is loaded. A tool that exposes drift state as an MCP tool call is a category-new capability.

The specific triangle of OpenAPI spec + TypeScript types + database schema as a combined drift detector does not exist as a standalone open source tool. Each layer has tooling (Prisma for DB, redocly for OpenAPI, ts-morph for TypeScript) but no tool connects all three.

## MVP scope (buildable in days)
- `npx driftguard check` - scans current directory, auto-discovers `openapi.yaml`/`openapi.json`, TypeScript interfaces and zod schemas, and Prisma `schema.prisma`
- Builds an entity map: for each named type/model, collects field definitions from all three sources
- Reports drift: "User.email is `string` in TypeScript, `format: email` in OpenAPI, but missing from Prisma schema"
- Exit code 1 on drift found (CI-friendly)
- JSON output flag for machine-readable results
- GitHub Action wrapper (`uses: driftguard/action@v1`) with annotation support

Day 1-2: Parser for each source (Prisma AST via `@prisma/internals`, OpenAPI via `@redocly/openapi-core`, TypeScript via `ts-morph`)
Day 3: Entity matching and field comparison engine
Day 4: CLI + output formatting + GitHub Action
Day 5: Published to npm, README, first real-world demo

## Stretch goals
- MCP server mode: `driftguard serve` exposes a tool AI agents can call - "check drift before writing to this endpoint"
- Auto-fix mode: `driftguard fix` generates a patch file to reconcile the layers
- Python support: FastAPI (Pydantic types + OpenAPI generation) and SQLAlchemy
- VS Code extension: inline warnings when you edit a type that drifts from the spec
- SaaS dashboard: drift history over time, trend across branches, team-level reporting
- OpenAPI generation from test traffic (the exact feature Optic had that has no replacement)

## Suggested stack
- TypeScript (Node.js 20+)
- `@prisma/internals` - Prisma schema parsing (no DB connection needed)
- `@redocly/openapi-core` - OpenAPI YAML/JSON parsing and validation
- `ts-morph` - TypeScript AST traversal for interface and zod schema extraction
- `commander` - CLI framework
- `zod` - internal validation and schema representation
- `@modelcontextprotocol/sdk` - MCP server for the stretch goal
- GitHub Actions YAML for the CI integration
- Vitest for tests

## Scale vision
DriftGuard starts as a CLI used by individual developers. The scale path is:

- **GitHub App (10k repos)**: Install once, get drift annotations on every PR. Becomes the standard "API consistency" check in CI, the way ESLint became the standard linter.
- **MCP Server (1M agent calls/day)**: As AI coding agents become the primary way teams write code, every agent that touches an API-adjacent file calls DriftGuard before committing. This is query volume, not just installs.
- **SaaS tier for enterprises**: Drift history, compliance reports, cross-service consistency checks for teams with 50+ microservices each with their own OpenAPI spec. SOC2 and ISO 27001 auditors are increasingly asking "does your API documentation match your implementation?" DriftGuard becomes the audit artifact.
- **Ecosystem integrations**: First-class support for FastAPI, Rails, Go (chi/echo), Laravel. The entity-matching engine becomes an API contract graph that spans polyglot services.

The infrastructure is simple: stateless analysis runs client-side. The SaaS layer is just storing results and surfacing history. A Postgres database and a Next.js dashboard is all the scale you need until 100k paying teams.

## Build-in-public angle
- Ship the CLI on day 5 and immediately run it against 10 popular open source TypeScript repos (Next.js examples, Hono, Fastify, trpc). Tweet the drift reports. "We found 23 field mismatches in [famous repo]'s OpenAPI spec." Open PRs to fix them - this proves the tool works and generates immediate community awareness.
- Weekly "Drift of the Week" post: pick one well-known project, run DriftGuard, show the before/after. Developers share these because they recognize the pain.
- Frame the tool explicitly as "the safeguard for AI-assisted development" - lean into the narrative that AI coding tools are fast but sloppy about cross-file consistency. Every Cursor and Claude Code user is the target audience.
- Open source from day one (MIT license), monetize the SaaS GitHub App later. The open source credibility is the distribution channel.
