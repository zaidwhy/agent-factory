# PinPoint

## One-liner
A CLI that analyzes which functions you actually import from each dependency, then filters changelogs and CVEs down to only the changes that touch YOUR code.

## The wow hook
"Your Lodash CVE only affects `_.template`. You never call `_.template`. Skip it safely." - PinPoint tells you this in 3 seconds, instead of you spending 20 minutes reading a changelog you don't understand.

## Who it's for
Solo developers and indie hackers drowning in Dependabot / Renovate PRs. They have 30-80 open dependency update PRs and no idea which ones are urgent and which are noise. They either merge everything blindly (risk) or ignore everything (also risk). The pain sharpens for vibe coders who have large dependency trees in code they didn't fully write and can't fully audit.

## Why now / why it doesn't exist yet
Two things converged in 2025-2026:

1. **Dependabot fatigue is at a crisis point.** A 2026 study found that 45% of AI-generated code has security vulnerabilities, and the typical vibe-coded project accumulates 30-41% more technical debt including unreviewed dependency updates. Devs are ignoring Dependabot PRs as noise, which means real CVEs are sitting unpatched.

2. **LLMs can now do changelog-to-usage mapping.** Until 2024, you'd need a purpose-built AST analysis + semantic changelog parser to do this reliably. Claude and similar models can now receive "here are the functions this user calls: X, Y, Z. Here is the changelog. Which entries are relevant?" and return accurate, actionable answers in a single API call.

Existing tools: Dependabot/Renovate (open PRs for everything, no personalization), Snyk (vulnerability-focused, no function-level filtering), DepLog (changelog highlights but not filtered to YOUR imports), Socket.dev (supply chain security, not usage-aware). None cross-reference your actual import call sites against the package's changelog or CVE.

Sources confirming the gap: https://dev.to/solobillions/i-tested-every-vibe-coding-security-scanner-2026-heres-what-actually-works-p9k | https://getautonoma.com/blog/vibe-coding-technical-debt | https://tinyhunt.dev/blog/deplog-review

## MVP scope
- **Import scanner**: Parse your project's source files (JS/TS via tree-sitter or @babel/parser; Python via the `ast` module) and build a map of `{ package_name: [list_of_identifiers_you_call] }`.
- **Version diff fetcher**: For each outdated dependency, fetch the package's GitHub releases or npm/PyPI changelog for the version range you're behind on.
- **Claude-powered relevance filter**: Send the import map + changelog to Claude with a structured prompt - "I call these functions. This is the changelog. Which entries affect me? What's my actual risk (none/low/medium/high)?"
- **CVE cross-reference**: Hit the OSV.dev API (free, no auth) to pull any CVEs for the package; filter them by whether the vulnerable code path overlaps with your usage.
- **CLI report**: Output a ranked list: `lodash 4.17.20 → 4.17.21 | YOU USE: _.debounce, _.throttle | CHANGELOG IMPACT: none | CVE: CVE-2021-23337 affects _.template (you don't use) | VERDICT: safe to skip`.
- **Config file**: `.pinpoint.json` to set language, include/exclude paths, LLM model.

## Stretch goals
- VS Code extension that shows PinPoint verdicts inline in `package.json` / `requirements.txt` (hover tooltip: "safe to update" / "read this first").
- Auto-PR comment: runs in CI and posts the filtered verdict as a comment on Dependabot PRs, so reviewers see "you only use X and Y from this package; this update doesn't touch them."
- Multi-repo mode: run across a monorepo and aggregate a single risk report.
- "Explain the breaking change" mode: for high-impact updates, generate a migration guide scoped only to the functions you actually call.

## Suggested stack
- **Python** - single executable CLI (`pipx install pinpoint`), fast to build, `ast` module is stdlib for Python scanning, `tree-sitter` bindings available for JS/TS. Avoids Node.js tooling complexity for a CLI.
- **tree-sitter** (Python binding) - accurate, language-agnostic AST parsing for JS/TS/Python source. Much more reliable than regex for finding import call sites.
- **Claude API (`claude-sonnet-4-5`)** - one API call per outdated dependency; structured output via tool use to get a JSON verdict (risk level, affected functions, relevant changelog lines).
- **OSV.dev REST API** - free, no auth, covers npm/PyPI/Cargo CVEs. One GET per package.
- **npm registry API + PyPI JSON API** - free, no auth, for fetching changelogs and version metadata.
- **Rich** (Python) - beautiful terminal output with color-coded risk levels.

Why not Node.js: Python's `ast` module gives you zero-dependency Python import parsing out of the box, and Python CLIs ship cleanly via `pipx`. Why not local LLM: changelog comprehension needs real reasoning; Claude's structured output via tool use gives consistent JSON verdicts without prompt fragility.

## Build-in-public angle
This project has a concrete, relatable origin story that every developer will recognize: "I had 47 open Dependabot PRs. I'd been ignoring them for weeks. Then I realized: I'm not ignoring them because I'm lazy. I'm ignoring them because they all look the same and I have no idea which ones matter." Ship the import scanner first (day 1), show the raw output on LinkedIn ("look what I found in my own codebase"). Add the Claude filtering layer on day 2 and demo the before/after: 47 PRs reduced to 3 that actually need attention. This demonstrates applied AI (not an LLM wrapper - the LLM is one component in a pipeline with real AST analysis), Python CLI craft, and a product instinct that comes from solving your own pain. The final post angle: "I turned dependency fatigue from a 3-hour audit into a 3-second command."
