# PinPoint

> Dependency risk analyst: scans your imports, fetches changelogs, checks CVEs,
> and asks Claude if you *actually* care about upgrading.

PinPoint goes beyond "this package has an update" — it cross-references the
changelog against the specific functions your code imports and gives you a
risk verdict for each outdated dependency.

---

## Quick start

```bash
# Install globally with pipx (recommended)
pip install pipx
pipx install ./pinpoint        # from this directory

# Or editable install for development
pip install -e .

# Required: set your Anthropic API key
export ANTHROPIC_API_KEY=sk-ant-...

# Optional: raise GitHub API rate limit from 60 to 5 000 req/hr
export GITHUB_TOKEN=ghp_...

# Initialize config in your project
pinpoint init /path/to/your/project

# Run a scan
pinpoint scan /path/to/your/project
```

## Commands

### `pinpoint scan [PROJECT_DIR]`

Scan a project for outdated dependencies and assess your actual risk.

```
OPTIONS:
  --config PATH            Path to .pinpoint.json (default: PROJECT_DIR/.pinpoint.json)
  --output [table|json]    Output format (default: table)
  --min-risk [none|low|medium|high]
                           Only show verdicts at or above this level (default: low)
  --verbose / -v           Show raw changelog text and call-site details
  --quiet / -q             Only show medium+ risk; suppress progress spinners
  --no-color               Disable Rich color output (also reads $NO_COLOR)
```

**Exit codes:**

| Code | Meaning |
|------|---------|
| 0 | Scan completed, no high-risk findings |
| 1 | Scan completed, at least one high-risk finding |
| 2 | Configuration error or missing API key |
| 3 | Network or API error |

### `pinpoint init [PROJECT_DIR]`

Write a default `.pinpoint.json` to PROJECT_DIR.

```
OPTIONS:
  --force / -f    Overwrite an existing .pinpoint.json
```

## CI / automation

```bash
# Fail the build on any high-risk dependency
pinpoint scan . --min-risk high --output json | jq .
```

PinPoint exits with code 1 if any `risk_level == "high"` verdict is found,
making it easy to wire into GitHub Actions or any CI pipeline.

## Configuration (.pinpoint.json)

See `.pinpoint.json.example` for a fully annotated config file.
All fields are optional — pinpoint works with zero config.

Key settings:

| Field | Default | Description |
|-------|---------|-------------|
| `language` | `"auto"` | `auto`, `python`, `javascript`, `typescript` |
| `model` | `"claude-sonnet-4-5"` | Anthropic model for analysis |
| `max_concurrent` | `5` | Parallel dependency lookups |
| `include_paths` | `["**/*.py", ...]` | Glob patterns for source files |
| `exclude_paths` | `["node_modules", ...]` | Path fragments to skip |

`anthropic_key` is **never** stored in the config file — always use the
`ANTHROPIC_API_KEY` environment variable.

## How it works

1. **Scan** — walk your source files with `ast` (Python) or `tree-sitter` (JS/TS)
   and build a map of every external package and the specific functions you import from it.
2. **Fetch** — for each outdated package, pull the changelog from GitHub Releases
   (falls back to npm/PyPI descriptions).
3. **CVE check** — query OSV.dev for vulnerabilities affecting your installed version.
4. **Analyze** — send one Claude API call per package with your actual import list,
   the changelog, and the CVEs. Claude returns a structured verdict: risk level,
   which changelog lines affect your code, and whether any CVE targets your functions.
5. **Report** — render a Rich table (or JSON) sorted by risk level.
