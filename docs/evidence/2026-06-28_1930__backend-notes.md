# Backend Notes - DriftGuard

## How to install

```bash
cd output/driftguard
npm install
```

Note: Node 24 is installed on this machine. The architecture.md specifies `>=20.0.0 <22` but the engine constraint was relaxed to `>=20.0.0` during development because Node 24 is LTS-compatible. Restore the `<22` upper bound before publishing if strict Node version pinning is required.

## How to run

```bash
# Type check
npm run typecheck

# Tests (108 tests, all pass)
npm test

# Build (ESM + CJS + .d.ts, output to dist/)
npm run build

# CLI smoke test
node dist/cli/index.js --help
node dist/cli/index.js check --help
node dist/cli/index.js serve --help

# Run against a project (from its root)
node /path/to/driftguard/dist/cli/index.js check
```

## Environment variables

| Variable | Default | Description |
|---|---|---|
| `DRIFTGUARD_CACHE_DIR` | `node_modules/.cache/driftguard` | Override cache directory |
| `DRIFTGUARD_NO_COLOR` | unset | Set to `1` to disable ANSI colors |
| `DRIFTGUARD_LOG_LEVEL` | unset | Set to `debug` for verbose stderr |
| `NO_COLOR` | unset | Standard no-color (also respected) |
| `DATABASE_URL` | unset | Only needed if running Prisma migrations - not used by DriftGuard itself |

Copy `.env.example` to `.env` for local development.

## Contract decisions made explicit

### 1. API contract adherence
All CLI flags, JSON output schema, GitHub annotations format, and MCP tool schemas match `architecture.md` exactly. The `CheckOutput.version` field is set to `"1"` as specified.

### 2. Zod schema extraction (scoped out)
Per architecture.md "weak decision": Zod schema shape extraction from static AST is not implemented in MVP. Only `interface` declarations and object `type` aliases are extracted from TypeScript. This is documented in README.md.

### 3. YAML parsing dependency
OpenAPI parser requires `js-yaml` at runtime for `.yaml`/`.yml` files. It is resolved via dynamic import (`await import("js-yaml")`). `js-yaml` comes as a transitive dependency of `@redocly/openapi-core` - no separate install needed. A `vendor.d.ts` declaration file provides the type signature since `js-yaml` does not bundle types in its `dist/js-yaml.mjs` export.

### 4. TypeScript glob (Node 20 vs 22+)
`fs/promises.glob` was added in Node 22. On Node 20, the TypeScript parser falls back to `fast-glob` (added as a direct dependency). This is transparent to callers.

### 5. Cache invalidation
Cache entries are keyed by `sha256(fileContent)`. If `@prisma/internals`, `@redocly/openapi-core`, or `ts-morph` change version, the entire cache is cleared via the manifest mechanism in `src/cache/index.ts`. This follows the Webpack/Babel `node_modules/.cache/` precedent.

### 6. Entity comparison threshold
Entities in only ONE source are silently skipped (not reported). This prevents flooding CI with internal Prisma-only tables. Entities in exactly TWO sources emit `entity-not-in-source` at `warning` severity by default. This matches the architecture tradeoff analysis exactly.

### 7. MCP server binary path
The CLI bin (`driftguard`) points to `./dist/cli/index.js` (ESM). The CJS counterpart is `dist/cli/index.cjs`. The shebang `#!/usr/bin/env node` is injected only by tsup's `banner.js` option to avoid the double-shebang bug that caused a parse error on Node 24 ESM.

### 8. Source file locations in Prisma
`@prisma/internals` DMMF does not expose line/column numbers for fields. The `location.line` and `location.column` in Prisma-sourced `FieldDefinition` objects are set to `0` as a documented sentinel. GitHub annotations for Prisma fields will therefore omit the `file`/`line`/`col` segments, falling back to the `title=DriftGuard::` form.
