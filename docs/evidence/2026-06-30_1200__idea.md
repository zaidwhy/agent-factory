# Receipts.dev

## One-liner
A developer portfolio that turns your real Git history into evidence-linked "skill receipts" - every claimed skill is backed by the exact diff you wrote - and lets a recruiter interrogate your actual code with an AI that can only cite real commits.

## The wow hook
A recruiter types "show me where this person handled race conditions" and gets back the actual lines of code the candidate wrote, deep-linked to the GitHub permalink, with a one-paragraph AI explanation grounded in that diff. No prose claims, no buzzwords - just receipts. Every skill on the profile is a clickable proof, not a self-assertion.

## Who it's for
Mid-level and senior engineers job hunting in 2026, who are losing signal because AI-written resumes and AI-generated side projects have made every candidate look identical on paper. They have real, hard-won work buried in commit history that a recruiter will never read. The pain: "I actually built the hard parts, but my resume looks the same as someone who vibe-coded a tutorial."

## Why now / why it doesn't exist yet
The verification crisis is fresh and measurable: a March 2026 Robert Half survey found 65% of hiring managers say AI-enhanced resumes have made candidate skills harder to verify, and there is no AI detection built into Greenhouse, Lever, or Workday - recruiters are reduced to gut-feel pattern matching ([Hiration, 2026](https://www.hiration.com/blog/ai-written-resume-detection/); [Gem, 2026](https://www.gem.com/blog/detect-ai-generated-resumes)). Meanwhile every existing GitHub tool (GitAnalyzer Pro, CodeTrace, RepoSense) stops at *stats and scores* - language pie charts, PR counts, gradient-boosted "profile ratings" ([github-analyzer topic](https://github.com/topics/github-analyzer)). None of them do the non-obvious thing: attribute authorship at the line level via git blame, classify what skill each *meaningful diff* demonstrates, and let a third party query that evidence in natural language with answers constrained to real code. The insight is a flip - stop scoring the developer, start producing court-admissible receipts for recruiters who no longer trust the resume.

## MVP scope (buildable in days)
- GitHub connect (public username for MVP, OAuth later): fetch a developer's repos and pull commits/diffs authored by *them* only (filter by committer email/login).
- Diff-to-evidence pipeline: for the top N repos, chunk the developer's own diffs and run an LLM pass that extracts concrete skill evidence ("implemented optimistic locking", "wrote a debounce hook") each tagged with file + line range + commit SHA.
- Skill graph UI: a clean profile page where each skill chip expands to the real diff snippet and a permalink to GitHub - the "receipt".
- Recruiter chat: RAG over the indexed code chunks; answers must cite a real file/line or say "no evidence found." This guardrail is the product.
- Shareable public profile link (the thing the developer puts on their resume).

## Stretch goals
- "Authenticity signal": flag repos that are forks/tutorials vs. original authored work, so the receipts are weighted by real ownership.
- PR-quality lens: pull review cycles and merge latency to show collaboration, not just code.
- Side-by-side compare for recruiters (two candidates, same skill, real diffs).
- Incremental re-index via GitHub webhooks so a profile stays live.

## Suggested stack
Next.js (App Router) + TypeScript frontend; FastAPI or Next API routes for the pipeline; GitHub REST/GraphQL API for diffs; Postgres + pgvector for code-chunk embeddings; an LLM API for extraction and the grounded chat; background jobs via a queue (e.g. Redis/BullMQ) so indexing is async. Deploy on Vercel + a managed Postgres.

## Scale vision
At millions of users the per-profile diff pipeline becomes a sharded, queue-driven indexing service with cached embeddings and webhook-based incremental updates, while the read path (public profiles + recruiter chat) stays a thin, globally cached RAG layer - the architecture changes from "index on demand" to "stream and cache," but the core unit, one verifiable receipt per skill, holds unchanged.

## Build-in-public angle
This is the rare portfolio project that *is* its own proof: I am building the tool that verifies developers, so every commit I push to Receipts.dev becomes a receipt inside Receipts.dev - a recursive demo recruiters will instantly get. The build-in-public arc writes itself: week one I ship the diff-to-evidence pipeline and post my own auto-generated skill graph; week two I add the grounded recruiter chat and challenge people to "ask my codebase anything"; week three I open it to other devs and share the wildest receipts. It demonstrates the exact stack hiring teams want - real-time systems, a non-trivial data pipeline over Git, RAG with hard grounding guardrails, and novel UX - wrapped in a story about the most relevant problem in tech hiring right now: trust.
